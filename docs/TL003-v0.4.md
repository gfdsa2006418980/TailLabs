# TailLabs TL003 完整遊戲規格書 v0.4

## 1. 專案定位

**專案代號：** TL003  
**平台：** Web Browser  
**類型：** 掛機增量 × Roguelike × 自動射擊 × 喪屍防守  
**單局基準時間：** 20 分鐘  
**長期遊戲結構：** 無限重複局 × 無限局外增量  
**操作平台：** Desktop + Mobile  
**部署方向：** GitHub Pages + Cloudflare

玩家率領最多三名傭兵守住拒馬。

傭兵平時自動射擊。

玩家負責：

- 招募與升級
- 戰場經濟
- Roguelike 三選一
- 四屬性 Build
- 拒馬防守
- 主動技能施放
- 局外天賦成長
- 核心天賦配置

遊戲不是純掛機。

自動攻擊負責基礎戰鬥，玩家透過長 CD 主動技能介入關鍵戰況。

---

# 2. 核心一句話

> 從只能殺死約五隻喪屍的破爛防線開始，透過一局又一局的防守累積天賦點，建立無限成長的傭兵火力網；局內以動能、火焰、生化與電能建立 Roguelike Build，並手動施放傭兵大招處理危險屍潮。

# 9. 局內高膨脹曲線

採方案 C。

初步 Balance Target：

| 數值 | 每分鐘倍率 |
|---|---:|
| 玩家有效 DPS | ×2.00 |
| 普通敵人單體 HP | ×1.80 |
| 敵人數量 | ×1.10 |
| 敵軍總壓力 | 約 ×1.98 |
| 局內收入 | ×1.85～1.95 |

因此：

```text
玩家：
×2.00 / min

敵軍：
1.80 × 1.10
≈ ×1.98 / min
```

正常 Build 只略微領先敵軍。

Build 不佳、過度投資經濟或忽略拒馬，都可能造成崩盤。

# 16. 傭兵招募

同類傭兵是否允許重複，可於後續收斂階段決定。

若允許重複：

```text
RecruitCost
=
BaseRecruitCost × 1.35 ^ Owned
```

初版以：

```text
×1.35 / 同類數量
```

作為測試值。

# 17. 傭兵等級

同類型傭兵共享等級。

例如：

```text

步槍手 Lv.25
```

代表所有步槍手共同套用：

```text
Lv.25
```

避免每一個 Unit 分別管理等級。

# 25. 主動技能冷卻

不設硬性最短 CD。

採用類似「技能急速」的等比例遞減模式。

定義：

```text
CooldownHaste
```

公式：

```text
EffectiveCooldown
=
BaseCooldown
/
(1 + CooldownHaste / 100)
```

例如基礎：

```text
30 秒
```

則：

| 技能急速 | CD |
|---:|---:|
| 0 | 30s |
| 100 | 15s |
| 200 | 10s |
| 500 | 5s |
| 900 | 3s |
| 1400 | 2s |
| 2900 | 1s |

---

# 26. 冷卻可以無限成長

Cooldown Haste：

```text
無上限
```

Effective Cooldown：

```text
無硬下限
```

因此後期允許：

```text
1 秒一顆手榴彈
```

甚至：

```text
0.5 秒
0.2 秒
0.1 秒
```

這不是 Bug。

而是 Infinite Incremental 後期的成長回饋。

---

# 27. 技能急速的邊際效益

因為使用：

```text
BaseCD / (1 + Haste)
```

所以成長自然遞減。

不需要：

```text
最大 80% CDR
```

等人工硬限制。

---

# 28. 高技能急速操作輔助

當技能 CD 進入極低區間後，玩家可能會因為高頻點擊疲勞。

因此後期可提供 QoL。

## 按住連續施放

例如手榴彈：

```text
按住技能
↓
保持目標位置 / 游標
↓
每當 CD 完成
↓
自動再次投擲
```

此時遊戲體感可從：

> 手榴彈

逐漸變成：

> 迫擊砲轟炸。

---

## 自動施放

後期天賦可以解鎖：

```text
AUTO
```

施放策略可以包含：

- 最大敵群
- 最靠近拒馬
- 最高 HP
- Elite 優先

這是操作疲勞解決方案。

不是限制技能急速成長。

# 37. 四屬性聯動

## 動能 + 火焰

直接攻擊附加燃燒。

## 動能 + 生化

直接攻擊附加腐蝕。

## 動能 + 電能

直接攻擊對 Shock 目標更加有效。

## 火焰 + 生化

Corrosion 越高：

```text

```

## 火焰 + 電能

Shock：

```text
同時提高 Burn 傷害
```

## 生化 + 電能

Corrosion：

```text
提高 Shock 效率
```

具體效果後續再進行卡牌設計。

```text
=

× (1 + Sum(Add))
× Product(More)
```

之後：

```text
RawDamage
↓
Defense
↓

↓
DamageAfterDefense
↓

↓

```

# 43. 火焰 DOT

為避免建立大量 Effect Instance：

敵人只需維護：

```text
BurnPower
BurnDuration
```

新 Burn：

- 增加 BurnPower
- 延長／刷新 Duration

Tick 時統一計算。

---

# 44. 生化 Corrosion

使用：

```text
CorrosionPower
```

而不是：

```text
Defense -999999%
```

概念公式：

```text
EffectiveDefense
=
Defense / (1 + CorrosionPower)
```

因此可以無限增長 CorrosionPower。

但防禦只會持續逼近 0。

---

# 45. 電能 Shock

使用：

```text
ShockPower
```

再轉換成：

```text
DamageTakenMultiplier
```

ShockPower 可以無限成長。

真正的 DamageTaken 效果採壓縮公式。

# 51. 初版得分公式

先採：

```text
SurvivalScore
=
floor(SurvivedSeconds / 30)
```

例如：

```text
30s = 1
60s = 2
5m = 10
20m = 40
```

經濟分：

```text
MoneyScore
=
floor(log10(TotalEarnedMoney + 1))
```

最後：

```text
TotalScore
=
SurvivalScore
+
MoneyScore
```

初版：

```text
TalentPointsEarned
=
TotalScore
```

係數之後再測。

# 54. 一般天賦效果採等比成長

基本形式：

```text
Multiplier
=
GrowthRate ^ Level
```

例如：

```text

1.08 ^ Level
```

則：

```text

Lv.20 ≈ ×4.66
Lv.30 ≈ ×10.06
Lv.50 ≈ ×46.9
Lv.100 ≈ ×2.2k
Lv.200 ≈ ×4.8m
```

符合 Infinite Incremental。

# 74. 設計硬規則

1. 傭兵平時自動戰鬥。

2. 玩家操作重點是 Build、經濟和主動技能。

3. 場上最多三名傭兵。

4. 每名傭兵只有一個主要主動大招。

5. 第一局應該只能殺約五隻喪屍。

6. 玩家 DPS 局內目標約每分鐘 ×2。

7. 局外成長為無限等比增量。

8. 技能急速無硬上限。

9. 主動技能 CD 無硬下限。

10. 超高頻操作使用按住連發／AutoCast 解決，而不是限制成長。

11. 動能＝直接傷害。

12. 火焰＝DOT。

13. 生化＝破防。

14. 電能＝增傷。

15. 爆炸只是 Mechanic，不是屬性。

16. 一般天賦無限成長。

17. 核心天賦只負責改變 Build。

18. 核心天賦最多裝三個。

19. 局內不保存。

20. 局外永久資料保持極簡。

21. 敵人不能根據玩家永久戰力同步 Scaling。

22. 舊內容最終必須可以被玩家碾壓。

23. Tag 能解決的效果，不為單一武器建立獨立公式。

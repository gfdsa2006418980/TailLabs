# TL001 效能修正與驗證（2026-10-18）

## 已實作

1. **靜態背景快取、畫面外物件隱藏**：場地 504 個裝飾小圓點與邊框只產生一次貼圖，避免每幀重新三角化。物件以攝影機可視範圍加 80 px 邊界判斷顯示；碰撞剛體仍保留。
2. **閒置停止繪圖與物理更新**：選單、玩法、排行榜、結算，以及物件全部停穩且鏡頭靜止時，停止 Phaser 主迴圈。滑鼠、觸控、鍵盤、操作按鈕、切換語言與視窗縮放會喚醒。獨立時鐘確保等待放置仍計時；選單和隱藏分頁不計時。
3. **限制變形與貼圖上傳**：桌機一般模式同時最多 2 隻使用 Canvas 局部變形，貼圖最多 30 Hz 更新。手機一般模式及超出預算的接觸改用圖片縮放；省電模式關閉碰撞回彈特效。固定及畫面外物件停止變形；放穩閃光以造型共用的點陣圖片取代即時輪廓繪製。
4. **省電模式與選單**：一般模式上限 60 FPS，省電模式上限 30 FPS，精簡閃光、停用背景模糊和排行榜展開動畫。手機首次預設啟用，可手動覆寫並儲存。使用保留截止時間的限幀器，避免引擎原有的間隔歸零造成 60／120 Hz 下額外漏幀。漢堡選單整合玩法、排行榜、重玩、EN／ZH／JA、模式與音量；所有對話框都有入口。
5. **重玩與結束清理**：清除剛體、接觸表、移動集合、變形貼圖與補間動畫；重設後更新一次物理偵測器，釋放上一局接觸參照。完整遊戲銷毀與場景關閉均清除 DOM／Phaser 監聽器、閒置計時器、音訊及物件。音效靜音時不建立振盪器，播放完即斷開節點；BGM 在開始遊玩時才預載。

上述模式調整的是繪圖與特效。凹形碰撞外框、物理回彈參數、60 Hz 物理步長、挑戰與計分規則維持原有設定。30 FPS 畫面下引擎仍依實際經過時間執行固定步長物理。

## 本機證據

環境：Windows、Chrome 155、硬體 WebGL。手機部分使用 Chromium 的 393 × 852 觸控與 iPhone UA 模擬，**不是 Safari 或 iPhone 14 Pro 實機測量**。

- npm test：77／77 通過，含 30／60 FPS 在 60／120／144 Hz 的排程、時鐘及儲存設定檢查。
- npm run build：主程式與 Worker 型別檢查、TL001 和 Commission 正式建置通過。
- 瀏覽器操作：三語切換與重載保存、音量保存、選單暫停／恢復、排行榜返回來源、鍵盤與滑鼠喚醒、觸控拖放、重玩、成功／失敗結算流程通過。
- 選單版面：320 × 568、393 × 852、852 × 393，三語無水平溢出；低高度視窗可捲動。
- 模擬隱藏／恢復事件：隱藏約 1.2 秒未加入遊戲時間。
- 完整銷毀：仍有變形與閃光時關閉遊戲後，物件、移動集合、接觸表、閒置計時器與遊戲 Canvas 均清空，無頁面例外。

### 合成壓力條件

以同造型蛇貂排列 5 欄、向上延伸，固定剛體不運動，保留一個合成操作狀態使畫面持續繪製；這是分離繪圖成本的條件，**不是 500 隻同時落下的實玩 FPS**。

| 條件 | 結果 |
| --- | --- |
| 玩法視窗，觀察約 2 秒 | 0 次遊戲繪圖 |
| 閒置等待放置，觀察約 2 秒 | 0 次遊戲繪圖，時間繼續 |
| 100 隻固定物件 | 約 0.16–0.19 ms／幀繪圖 |
| 500 隻固定物件 | 含手持共 501 隻，61 隻可見；約 0.18–0.20 ms／幀繪圖 |
| 500 隻、8 隻反覆觸發特效，一般模式，觀察約 3 秒 | 最多 2 張變形貼圖；180 次上傳 |
| 同條件省電模式，觀察約 3 秒 | 約 29.9 FPS；0 次特效 Canvas 重畫、0 次上傳、0 張變形貼圖 |

100／500 隻交替重玩 10 次：

- 每次重設後：2 個剛體（底座與手持）、1 隻手持、0 張變形貼圖、0 補間、0 接觸表項目、0 移動物件。
- 共用貼圖保持 23 張（固定單一造型測試），未隨重玩累積。
- GC 後 JS heap 約 7.8–8.3 MiB；本次短測未見持續成長。
- 桌機重設約 1.3–6.2 ms。這個耗時不代表手機重設耗時或 GPU 記憶體上限。

## 尚待實機確認

iPhone 14 Pro Safari 的持續幀率、溫度與耗電，以及 PC 長時間遊玩的溫度，仍需要實機比較。上述結果證明背景重畫、變形上傳與閒置迴圈的負擔已降低，不能換算為實際降溫幅度。
